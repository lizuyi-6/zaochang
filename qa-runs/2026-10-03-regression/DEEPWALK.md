### P-101【高】手机端 6 个主目的地完全没有导航入口

**运行时证据**(390×844,已登录)

遍历 7 个种子页(`/`、`/discover`、`/circles`、`/bookshelf`、`/collections`、`/challenges`、`/docs`),每页逐屏滚动到底,收集「**当前视口内 + 有尺寸 + 命中测试通过**」的链接:

```
✓ /             可从全部 7 页点到
✓ /discover     可从全部 7 页点到
✓ /circles      可从全部 7 页点到
✓ /bookshelf    可从全部 7 页点到
✓ /feed         仅首页 y=2500 处可点(位置极靠下)
✓ /lattice/     仅首页
✗ /challenges   无入口
✗ /collections  无入口
✗ /docs         无入口
✗ /studio       无入口
✗ /developers   无入口
✗ /wallet       无入口
```

**源码层确认**(`app/components/site-shell.tsx`)
```ts
const mobileTabHrefs = ["/", "/discover", "/bookshelf", "/circles"];   // :58
...
<nav className="deep-mobile-nav" aria-label="移动端导航">              // :362
  {mobileTabItems.map(...)}                                          // 只有这 4 项
  <Link className="deep-mobile-create" href="/studio/new" ...>        // :368
</nav>
```
移动端导航**只渲染这 4 项 + 一个「发布作品」FAB**,**整个文件里不存在任何溢出/更多/ellipsis 触发器**。被裁掉的 6 项因此**没有任何兜底入口**。

**用户后果** —— 手机用户只能到达 12 个主板块中的 6 个(首页、探索、圈子、书架、见界,加上要滚到 y=2500 才出现的动态)。挑战、收藏、文档、创作台、开发者、果子钱包**只能靠手输 URL**。`/studio/new`(发布)可点,但 `/studio`(创作台列表)不可点 —— FAB 通向的是一条死胡同的入口。

**注意**:`mobileTabHrefs` 的注释写的是「手机底部 tab 的**主入口白名单**」,裁剪 tab 本身是有意的;缺的是**被裁掉那 6 项的溢出菜单**。

**复现**
```bash
# 390x844 视口打开 https://aetherstudio.top/,整页滚到底
# 底部只有 4 个 tab + 发布 FAB;全页无「更多」入口
```

### P-102【中】账户菜单按 `Esc` 不关闭(全站每页复现)

**观察** —— 7 个主站页全部:`Esc 测试: 打开=true → Esc后=true ✗`

**判别实验**(`59-esc-probe.json` + 截图)

| 试验 | 结果 |
|---|---|
| 鼠标点开 → Esc | `aria-expanded` 仍 `true`,**面板仍可见** |
| 点空白处 | `aria-expanded` → `false`,**能关** |
| 派发 Escape 到 document | 事件**被收到** ⇒ 不是注入问题,是**没绑处理器** |

键盘用户能打开账户菜单(个人主页/编辑资料/开发者接入/退出登录)却**无法用 Esc 关闭**。WCAG 2.1.1 / 2.4.3。

**为什么单独记** —— `f725678` 修过**完全同类**问题(「白板反馈/设置弹窗 Esc 不可退出——补 Esc 关闭」),那次覆盖的是白板面板;**站点壳层的账户菜单(`.deep-account`)没被覆盖**。修复模式已在仓里,补一处即可。

### ~~P-104 见界侧栏折叠按钮键盘聚焦时不可见~~ → **推翻,产品是对的**

我据 `shell.css:46-54` 的 `opacity: 0` + 仅 `:hover` 推断「键盘 Tab 到它时完全看不见」,并判定为 WCAG 2.4.7 焦点可见失败。**判别实验推翻了它**:

| 状态 | opacity | outline | box-shadow |
|---|---|---|---|
| 未聚焦 | `0` | `none 0px` | `none` |
| **键盘聚焦** | **`1`** | **`solid 2px rgb(194,74,46)`** | `rgb(255,253,248) 0 0 0 3px` |

存在我 grep 时漏掉的 `:focus-visible` 规则,聚焦会点亮按钮并给出 2px 珊瑚焦点环 + 3px 光晕。**产品正确。** 残留仅:按钮 24×24(手机端展开按钮 32×32),低于 44px 但满足 WCAG 2.5.8 AA 的 24×24 下限,属提示不属缺陷。

## 五、被推翻的自身嫌疑(4 项,全部留档)

深交互的价值有一半来自它把**我的错误**也照出来了:

| 我的初始判断 | 处置 | 依据 |
|---|---|---|
| 侧栏点「圈子」不跳转、后续点击全被挡 ⇒ 导航坏在 /feed | **推翻自己** | `a:has-text("圈子")` 会命中所有「文本包含该串」的元素及其祖先(含侧栏 14×14 圆点链接)。换精确 `a[href="/circles"]` 后 `/feed→/circles→/challenges` 全部正常 |
| 集市页点击后正文少 2651 字 ⇒ 内容丢失 | **推翻自己** | 那是点到「AI & Data Science」分类,5 门课筛到 2 门,正常筛选 |
| `/galaxy` 零可滚容器 ⇒ 内容被截断 | **推翻自己** | `galaxy.module.css:4-7` 是 `position:fixed; height:100dvh; overflow:hidden`,刻意的全屏沉浸式 |
| 37 页「有交互反馈」是覆盖充分 | **推翻自己** | 那 37 次几乎全是同一个头像菜单(`button[aria-expanded]` 文本「造」),它排第一个、吃掉点击预算。已加跳过规则并单独做点击深化 |

**驱动器本身修掉的 3 个 bug**(都会造成假阴性):
1. `scroll-behavior: smooth` 下赋 `scrollTop` 会启动动画,紧接着读回仍是旧值 → 误判「没动」提前 break(`/developers/docs` 1174px 只滚 1 步)
2. 每步重挑「最大可滚动元素」→ 懒加载元素出现后目标换人,下半段永远滚不到
3. 只取最大容器 → 漏掉「页面不滚动但固定区域可滚」这一类(`/feed` 的侧栏 62px 整段没测到)
