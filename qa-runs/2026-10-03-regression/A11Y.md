## 二、发现

### P-102【中】账户菜单按 `Esc` 不关闭(全站每页复现)

**观察** —— 7 个主站页面(首页/探索/开发者文档/钱包/发布新作品/书详情/登录页)全部:
```
Esc 测试: 打开=true → Esc后=true   ✗ 未关闭
```

**判别实验**(`59-esc-probe.json`,含截图 `esc-*.png`)

| 试验 | 结果 |
|---|---|
| 鼠标点开 → Esc | `aria-expanded` 仍为 `true`,**面板仍可见**(截图 `esc-2-mouse-after-esc.png` 可见菜单完整展开) |
| 点空白处 | `aria-expanded` → `false`,**能关** |
| 派发 Escape 到 document | 事件**被收到** ⇒ 不是我的注入问题,是**没有绑定处理器** |

**用户后果** —— 键盘用户可以打开账户菜单(个人主页 / 编辑资料 / 开发者接入 / 退出登录),但**无法用 Esc 关闭**,只能靠「点空白处」这个对键盘用户不成立的退路,或一路 Tab 走出去。WCAG 2.1.1(Keyboard)/ 2.4.3(Focus Order)。

**为什么值得单独记** —— 你们在 `f725678` 已经修过**完全同类**的问题:
> 白板反馈/设置弹窗背板挡整页属模态设计,但 Esc 不可退出——补 Esc 关闭(panel 已有,对齐)

那次覆盖的是白板面板。**站点壳层的账户菜单(`.deep-account`)没被覆盖**。修复模式已经在仓里,补一处即可。

**复现**
```bash

# 菜单不关闭。点页面空白处则关闭。
```

### P-103【低】见界 SPA 没有「跳到主要内容」skip link

**观察**
```
主站:  Tab 1 → a.skip-link  "跳到主要内容" 100x36     ✓
```

## 三、被推翻的自身怀疑

### ~~侧栏折叠按钮键盘聚焦时不可见~~ → **推翻,产品是对的**

**初始怀疑** —— `shell.css:46-54` 里:
```css
.hk-sidebar-collapse { padding: 4px; opacity: 0; }
.hk-sidebar:hover .hk-sidebar-collapse { opacity: 1; }
```
只有 `:hover` 没有 `:focus-within`,而按钮实测 **24×24**,故推断「键盘 Tab 到它时它是 `opacity: 0`,完全看不见」(WCAG 2.4.7 焦点可见失败)。

**判别实验**(`60-collapse-focus.json`)

| 状态 | opacity | outline | box-shadow |
|---|---|---|---|
| 未聚焦 | `0` | `none 0px` | `none` |
| **键盘聚焦** | **`1`** | **`solid 2px rgb(194,74,46)`** | `rgb(255,253,248) 0 0 0 3px` |
| 鼠标 hover | `1` | — | — |

聚焦时 `isActiveElement: true` 且 `sidebarHovered: false` —— 说明**存在我 grep 时漏掉的 `:focus-visible` 规则**,聚焦会点亮按钮并给出 2px 珊瑚色焦点环 + 3px 白色光晕。**产品正确,是我的 grep 不完整。**

> 附带一条方法论:我的焦点环检测只看 `outline` / `box-shadow`,**不看元素自身 `opacity`**。本例中它报了「焦点环=✓」而元素其实在未聚焦时不可见 —— 这个检测器会同时产生假阳性和假阴性,后续复用需补 opacity 判断。

**残留(不判为缺陷)**:`.hk-sidebar-collapse` 桌面 **24×24**、`hk-sidebar-expand` 手机 **32×32**,低于项目声称的 44px,但满足 WCAG 2.5.8 AA 的 **24×24** 下限,且是次要控件。
