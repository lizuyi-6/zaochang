# 深度理解型教材创作与平台发布全流程技能 (Deep Book Builder)

## 一、 技能定位与核心目标

本技能用于指导 Agent 完整创作一本面向计算机专业、考研 408 或深度技术爱好者的**高密度、理解型技术教材**，并将其自动化构建、校验并挂载至造场（Zaochang）知识库与阅读器平台。

核心教学哲学：**“让读者在脑中建立一台真正可以运行起来的计算机/系统。”**

---

## 二、 防偷懒与防缩水核心规范（Anti-Laziness Directives）

为了根治大模型在创作长篇教材时容易出现的“提纲化、PPT化、过度抽象、提前宣布结论”等偷懒恶习，必须严格遵循以下铁律：

### 1. 严禁使用任何 AI Emoji
- 严禁出现 🚀, 💡, 📌, 🎯, 🧠, ⚡ 等任何装饰性表情符号；
- 语言风格必须是严谨、凝练、具有工业与学术质感的教科书风格。

### 2. 严禁“先宣布答案，再补解释”
- 每一个核心机制（寄存器、补码、CLA、Cache、虚拟内存、Forwarding、DMA 等）必须遵循**“认知冲突演进”**：
  $$\text{真实问题} \to \text{自然的错误直觉} \to \text{物理推演撞墙 (总线争用/输入震荡/延迟爆炸)} \to \text{新机制破土而出} \to \text{建立脑内模型}$$

### 3. 所有关键机制必须带“具体真实数值”全景贯通运行
- 绝不能长期停留在抽象符号推导（如仅仅写 $MDR \leftarrow M[MAR]$）；
- 必须赋予具体物理参数：给出真实的内存地址（如 `0x00401000`）、具体十六进制机器码（如 `0x012B1820`）、寄存器初始值（`R1=2, R2=3`）、时钟节拍（$T_1 \sim T_6$）和具体控制信号电平（$PC_{\text{out}}, MAR_{\text{in}}, \dots$）。

### 4. 严禁把正文写成“列表文章”
- 列表仅用于最终总结和归纳；
- 承担推导与机制解释的部分，必须展开完整的因果逻辑链条，绝不能用几个简短要点敷衍了事。

### 5. 模块化工程防压缩策略
- **绝不要试图在单次对话中一次性生成 40 个章节**；
- 必须采用**模块化脚本构建器体系（`scripts/builder/`）**：
  - 将全书拆分为分卷文件（如 `part1.mjs` ~ `part10.mjs`）；
  - 每一卷专注于 3~6 个章节的深度推导；
  - 由总控脚本 `build-all.mjs` 统一汇编编译成完整的 SQL 导入文件。

## 三、 单章标准化结构模板（14 步法）

每个章节的正文编写必须覆盖以下 14 个教学模块：

```text
01 一个真实问题 (从现实代码或硬件现象切入)
02 我们最自然的第一反应 (初学者的直觉模型)
03 如果真的这样实现，会发生什么？ (推演物理冲突/逻辑矛盾)
04 原来的模型在哪里撞墙？ (揭示核心矛盾: 如速度不匹配/总线争用)
05 新机制为什么必须出现？ (为什么该硬件结构不可替代)
06 建立正确脑内模型 (硬件连线与核心组件职责)
07 跑一个完整案例 (给具体地址、机器码、时钟节拍与寄存器值推演)
08 信息流、数据通路与状态变化全景表 (节拍-信号-活跃/闲置部件矩阵)
09 更精确的技术表达与抽象层区分 (高级语言 vs ISA vs 微架构 vs 现代工业实现)
10 性能模型或数学公式 (逐一解构每个物理变量的现实意义)
11 最小实验 / 思想实验 (配套 Python/C/GDB 验证脚本)
12 408 对应考点与真题命题陷阱 (深入剖析考题背后的脑内模型偏差)
13 本章完整心智模型复盘 (闭目可想的连续动态画面)
14 下一章自然产生的问题 (引出下一个不可调和的硬件矛盾)
```

## 四、 平台工程化构建与挂载全流程

### 第一步：编写分卷构建模块 (`scripts/builder/partX.mjs`)
在 `scripts/builder/` 目录下组织分卷内容：
- `core.mjs`：书根节点（`is_book: 1`）与序言；
- `part1.mjs` ~ `partN.mjs`：各大分部（Part）与子章节（Chapter）。

**排版关键细节**：
1. **KaTeX 独立块级排版**：包含分式（`\frac`）、求和、极限等复杂运算的公式，一律采用 `$$...$$` 独立居中排版，避免行内行高挤压；
2. **Mermaid 图表规范**：节点标签若含括号或特殊字符必须加双引号（如 `id["标签 (额外信息)"]`），连接线使用标准命名；
3. **JS 模板字符串转义**：
   - 代码块反引号必须转义为 `\`\`\`c` 或 `\`\`\`mermaid`；
   - LaTeX 转义字符前必须双反斜杠：`\\frac`, `\\text`, `\\times`, `\\Delta`, `\\xrightarrow`, `\\mu`。

### 第二步：总控编译脚本 (`scripts/builder/build-all.mjs`)
编写 Node.js 编译总控脚本，执行以下任务：
1. 聚合所有 Part 的文档对象；
2. 自动生成标准 SQL `INSERT INTO docs ...` 语句；
3. 自动化校验：
   - 正则扫描是否含有残留 AI Emoji（`[\u{1F300}-\u{1F6FF}...]`）；
   - 统计文档总节点数与字节大小；
4. 输出到 `backups/import-[book-name].sql`。

### 第三步：本地数据库挂载 (`scripts/import-local-[book-name].mjs`)
挂载到本地 Miniflare D1 SQLite 数据库：
1. 遍历定位 `.wrangler/state/v3/d1/miniflare-D1DatabaseObject/*.sqlite`；
2. **外键约束处理**：检查 `members` 表中是否存在 `author_email`，若不存在则先插入作者记录，防止触发 `FOREIGN KEY constraint failed`；
3. 执行编译好的 SQL 文件；
4. 查询验证节点总数。

### 第四步：样式与前端路由适配排坑
1. **KaTeX CSS 引入**：
   - 严禁在 RSC（React Server Components）服务端组件中直接 `import "katex/dist/katex.min.css"`（否则在 Vite 开发模式下会被拦截为 `text/javascript` 导致 MathML 与 HTML 重叠）；
   - 正确做法：在 `app/globals.css` 顶部增加 `@import "katex/dist/katex.min.css";`，由 PostCSS/Tailwind 统一编译为纯 CSS 样式流。
2. **书架路由规则**：
   - 书籍主页与章节路径统一挂载在 `/bookshelf/[book-slug]/[part-slug]/[chapter-slug]`。

## 五、 自动化质量自检清单（Pre-Flight Checklist）

在交付给用户前，必须逐项核对：

- [ ] **无偷懒检查**：每章是否均有具体数值推演（$T_1 \sim T_6$、真实地址、寄存器状态）？
- [ ] **零 Emoji 检查**：运行正则扫描，确保没有任何 AI Emojis；
- [ ] **公式排版检查**：所有复合分式与大公式均使用 `$$...$$` 块级展示；
- [ ] **Mermaid 渲染检查**：所有数据通路流图与时序图语法闭合无报错；
- [ ] **数据库一致性**：`parent_id` 层级拓扑无断裂，`author_email` 外键有效；
- [ ] **本地服务验证**：启动开发服务器，各章节 HTTP 状态码均为 200 且排版美观。
